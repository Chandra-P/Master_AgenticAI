# Backend implementation report

Implemented contract routes in `tagalong/app.py`, identity/snapshot invariants in `core.py`, real Supabase HTTP session verification and OpenAI/Pinecone adapters in `providers.py`, durable Postgres repository and a leased ingestion worker. Existing known accounts can be shared by email, owners only. Browser-supplied membership, confirmed preferences, existing chat/assistant messages and other actors votes cannot be overwritten. Revision mismatch returns 409. Model output cannot execute actions or change confirmed preferences; explicit proposal confirmation is required.

The migration enables RLS with no authenticated mutation grants. The server uses an administrative DATABASE_URL. Normalized plan/proposal/source/job projections coexist with one locked JSON state row. That row makes all authorization, revision checks, messages, proposals and job changes atomic across API and worker processes. This is deliberately serialized and suitable for an initial small deployment; it is not a horizontally scalable storage design. Supabase Realtime invalidation uses `tagalong_revisions` filtered through membership RLS.

Sources use stable vector IDs in namespace `tagalong:{plan_id}`. Retrieval is conditional for historical/document questions. Retrieved IDs are looked up in authoritative database state and checked for plan, deletion and version before generation and again before committing citations. User chat and text documents enqueue ingestion. Deletion tombstones private source text and queues vector deletion. Leases expire, retry up to five attempts with bounded exponential delay, and prevent overlapping jobs on the same source while a lease is active. Failed jobs remain visible in durable storage for operator repair.

Dependencies are pinned in pyproject.toml with uv.lock and were installed in backend/.venv using managed Python 3.12.15. OpenAI uses Responses strict JSON schema and configurable OPENAI_MODEL (default gpt-4.1-mini); embeddings default text-embedding-3-small (Pinecone index must use matching 1536 dimensions). Pinecone 7.3.0 uses `_request_timeout=15`, and its pool is bounded to four threads. OpenAI timeout is 25 seconds with one retry. Supabase requests timeout after 10 seconds. Provider response errors return redacted messages.

Run from backend: `uv sync --frozen`, `uv run uvicorn tagalong.app:app --host 0.0.0.0 --port 8000`; separate worker: `uv run python -m tagalong.worker`. Required server-only variables: DATABASE_URL, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, OPENAI_API_KEY, PINECONE_API_KEY, PINECONE_INDEX_HOST, CORS_ORIGINS. Missing connections return unavailable rather than demo data. Health capabilities advertise unavailable Places/calendar integrations honestly. Documents: POST/GET `/v1/plans/{id}/documents`, DELETE `/v1/plans/{id}/documents/{source_id}`; only JSON text/plain input is accepted.

Validation: initial API import test failed before implementation. Expanded malformed snapshot test failed before Pydantic validation was added. Competing worker lease test failed before per-source exclusion was added. Current credential-free suite has 10 passing API/workflow tests, covering auth denial, cross-plan access, optimistic conflicts, sharing, forged identity, snapshots, vote replacement, proposal confirmation, citations, stale/deleted evidence, provider errors, worker retries and leases. SDK construction smoke successfully builds real LangGraph and Pinecone classes without network credentials. Live Supabase/Postgres migration, OpenAI generation and Pinecone data-plane checks have not been performed; deployment credentials and service provisioning are required. Places and calendar are disabled. No claimed live deployment.

Additional detail: document embeddings use bounded 6,000-character chunks, stable per-source chunk IDs and source/version metadata; tombstones preserve the chunk count so deletion removes all indexed chunks. Job leases last 30 minutes to cover the bounded multi-chunk provider calls. Citations deduplicate chunk hits into authoritative sources.

Review fixes: pending preferences are projected from pending proposals into Plan and remain server-controlled during snapshot saves. Assistant avoids duplicating an already-persisted last user message. Roles are validated against server membership. LangGraph now actually routes exact facts directly to generation and historical questions through conditional retrieval plus a database source-resolution callback before generation. API applies an atomic durable limit of ten assistant requests per actor per minute; provider output is capped at 2,000 tokens, context chat is limited to the last twenty truncated messages, and evidence text is bounded. Test-only browser ASGI factory: `uv run uvicorn tests.http_fixture:app_factory --factory --port 8000` from backend (accepts explicit test-alice/test-bob tokens; never referenced by production app). Latest suite: 14 passed.

## Validation and persistence improvements

Creation now validates ISO YYYY-MM-DD dates, rejects reversed ranges and whitespace-only titles, trims names, and initializes local renderable images (`/images/coast.jpg` for trips, `/images/restaurant.jpg` for outings), a date label, a date poll and planning tasks. Snapshot validation limits messages to 1,000, preferences to 200, members to 100, polls to 100 (2–20 unique nonempty options), itinerary to 200 and tasks to 200; strings and citation excerpts are bounded and unknown fields rejected. Existing poll choices cannot be reordered or renamed after a vote. Model JSON is parsed through a strict bounded schema; invented citations are rejected instead of silently omitted. Generation preserves authoritative budget, caps recent human context at 40,000 serialized characters, strips prior assistant citation content, and uses verified source excerpts.

Owner-only DELETE `/v1/plans/{plan_id}/members/{user_id}` revokes membership (owner removal is rejected). Authorization is rechecked when resolving evidence and committing assistant results, so a revoked actor cannot retrieve plan facts or sources, including revocation during a graph call. Optimistic snapshot concurrency is tested with actual simultaneous threads.

The Postgres unit of work now detects unchanged state and performs no UPDATE/INSERT/DELETE for reads or empty worker polls. Changed transactions update only changed normalized plans/proposals/sources/jobs and apply narrow membership differences; unrelated revisions are not republished. It still uses one locked aggregate row, with the initial scale limitation described above.

Embedding dimensions are configurable using OPENAI_EMBEDDING_DIMENSIONS (default 1536). Set 768 to reuse an existing compatible 768-dimensional index with OpenAI text-embedding-3-small reduction; plan data stays in isolated `tagalong:{plan_id}` namespaces. The worker verifies the existing Pinecone dimension before ingestion using a bounded read-only stats call. Constructor setup does not make external network calls. Health now probes the database schema read-only and returns 503 for missing configuration/schema/connectivity; healthy in-memory fixtures remain 200. OpenAI/Pinecone liveness is a separate release check, not implied by database readiness.

`backend/TESTING.md` documents the opt-in real SQL test. `TAGALONG_TEST_DATABASE_URL` must identify a separate empty migrated Supabase database; without it, one integration test is explicitly skipped. The test uses generated auth users and a wrapping rollback, executes projection SQL, tests authenticated RLS visibility, and tests denial of direct state access. No claim of executing that test against a live database is made here.

Final document-route hardening: source metadata now records `kind` (`message` by default, `document` for uploads), tombstones retain the original kind, and legacy untyped sources are treated as messages. GET documents lists only uploaded documents, and DELETE documents returns 404 for chat/legacy message source IDs. Existing document response fields are retained. Focused regression tests were observed failing first and then fixed; final suite result follows below. Provider code was left untouched during this task.
Final verification after document-route hardening: 40 passed, 1 explicit PostgreSQL integration skip; compileall passed.

Incremental update endpoint added: PATCH `/v1/plans/{id}` accepts strict expected_revision plus 1–200 bounded data-only patch operations (add/replace/remove; path depth <=12). It checks plan access and current revision before applying operations, rejects protected roots, uses strict object keys/array indices and appends only at array length, then reuses the full PUT snapshot invariants within the same repository transaction. PUT remains compatible. Tests first failed405 for the missing endpoint, then passed for a scalar vote on a 380KB chat history, valid chat append/ingestion, stale and unauthorized requests, protected fields, malformed paths/operations, forbidden other-member votes, limits and all-or-nothing rollback.

## Embedded worker free-pilot change

Added opt-in `TAGALONG_EMBEDDED_WORKER=true` support to the FastAPI lifespan. It starts a daemon only with configured repository/authentication/AI dependencies and consumes the same Postgres-backed leased jobs through `process_one`. Dimension validation runs in the background, retries failures with an interruptible 15-second wait, and prevents indexing until successful; successful validation is once per lifecycle. Processing waits two seconds between polls, including empty/failed queues. Background exceptions are caught without logging details. Shutdown signals stop and uses a bounded two-second join; normal short tasks exit fully, and in-flight provider work retains its existing timeout/lease recovery behavior.

Default false preserves the standalone worker. Free-service idle sleep pauses embedded ingestion, while durable Postgres jobs remain; no keepalive mechanism was added. Safe `/health` metadata exposes indexing_mode and indexing_worker_running without claiming provider readiness. Transient Pinecone failures do not fail database/API health. New lifecycle tests were observed failing before implementation, then passed with injected synthetic sources/providers; they include disabled no provider calls, transient failure recovery, mismatch no-index/no-lease behavior, health metadata, missing components and bounded shutdown/thread cleanup. No production credentials, live source data, live provider requests, commits or pushes were used for this task.
Final verification for embedded ingestion: 68 passed, 1 explicit SQL integration skip; compileall passed. Eight new lifecycle tests pass; existing persistence/lease tests remain passing.
