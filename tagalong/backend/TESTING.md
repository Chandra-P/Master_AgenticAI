# Backend verification

Run the credential-free suite from `backend` with `uv run pytest tests -q`. It exercises the API through FastAPI's HTTP test client, a real transactional in-memory repository, graph routing, invalid provider output, citations, access revocation and concurrent snapshots. Repository fake-cursor tests assert which SQL mutations occur; they are not a substitute for PostgreSQL execution.

For a real database check, start a dedicated disposable local Supabase stack (or provision a separate empty test project), apply `supabase/migrations/202611040001_tagalong.sql` with its administrator connection, and supply that connection as `TAGALONG_TEST_DATABASE_URL` only. Run `uv run pytest tests/test_postgres_integration.py -q`. The test deliberately never reads `DATABASE_URL`, refuses a database containing plans/memberships, uses generated auth-user UUIDs, and rolls back every inserted row. It checks real projection SQL, revision updates, membership RLS, and denial of direct state access as the authenticated role. It needs a Supabase-compatible auth schema, authenticated/anon roles, and Realtime publication; a plain PostgreSQL server alone does not provide those. CI without this dedicated URL reports one explicit skip.

Browser tests can start `uv run uvicorn tests.http_fixture:app_factory --factory --host 127.0.0.1 --port 8000`. This explicit test module uses in-memory persistence and only `test-alice`/`test-bob` bearer tokens. The production entrypoint is `tagalong.app:app`; it never enables fixture authentication through environment flags.

Before a public release, also execute the real two-account frontend flow against the deployed API: sign in, create a plan, share with the second signed-in email, add text evidence, run the worker, request historical evidence, verify citation/version, confirm a proposal, revoke access and verify the removed actor gets 404, and verify an old snapshot gets 409. Test OpenAI and Pinecone with the configured model/index dimensions, authenticate expired tokens, and verify Supabase Realtime only reveals authorized plan revisions. These live checks have not been represented as completed by the credential-free suite.

## Incremental snapshot updates

PATCH `/v1/plans/{id}` accepts `{expected_revision: integer, patches: [{op: "add" | "replace" | "remove", path: (string | integer)[], value?: JSON}]}` and returns the updated Plan. Use 1–200 operations with path depth 1–12. Roots are limited to title/location/date/start/end/budget/image/messages/polls/itinerary/tasks. Array additions only append at the current length; other array operations require existing nonnegative integer indices. Object additions require a new key; replace/remove require an existing key. Boolean indices are rejected. The server loads the full authorized snapshot, applies patches to a copy, and executes all existing snapshot invariants with the same optimistic revision guard inside one transaction. PUT remains available. Small patches therefore work when a legal accumulated message history exceeds the frontend request body cap; the history is not retransmitted in the request.

## Opt-in embedded ingestion for a free pilot

Set `TAGALONG_EMBEDDED_WORKER=true` on the API process to consume the durable ingestion queue inside a lifecycle-managed daemon thread. The default is false, preserving the standalone `python -m tagalong.worker` setup. A thread starts only when the repository, authentication provider and AI provider are configured. Startup itself does not wait for Pinecone: a failed read-only dimension check retries after 15 seconds without leasing or indexing a source, and API/database health remains available. Once the check succeeds it is not repeated in that lifecycle. Each poll reuses the existing `process_one` transaction/lease/retry rules, and waits two seconds even after processing work. No exception, credential or source text is logged by this runner.

Lifespan shutdown signals an interruptible stop event and joins for at most two seconds. Normal completed/short tasks leave no thread behind. An already-running provider request keeps its existing bounded timeout and may outlive that join as a daemon; a process restart recovers unfinished work through the existing durable lease expiration. This adds no keepalive traffic. When a free web service sleeps, its embedded worker pauses too; queued work remains in PostgreSQL until the service is awake and eligible leases can be processed.

Health adds `indexing_mode` (`embedded` when explicitly enabled, otherwise `external`) and `indexing_worker_running` (whether the managed thread is alive). These reveal process state without credentials, exception details or source text. A true running flag does not claim an external provider is currently healthy: the thread can be backing off after a provider failure. Existing plan readiness still depends on database/auth configuration and the schema health probe.

The credential-free lifecycle tests use synthetic queued sources and injected providers only. They cover enabled processing, disabled no-op behavior, transient validation recovery, mismatch safety, missing configuration, safe health metadata, bounded shutdown and thread cleanup. No live data/provider calls were made for this change.
