# Methodology and limits

The sample corpus is seeded Python rendering of fictional banking campaigns, with no actual customer records. Its 130 source files comprise 80 campaign documents, 30 shared guides and 20 learning guides (12 original plus eight requirements-pack sources). The source manifest is separate from question gold and evaluation outputs. The framework can be adapted to an owner's campaign knowledge base through its ingestion and metadata contract; this sample is not the SEC tutorial's dataset.

Three chunkers share a 500-token maximum and 50-token overflow overlap measured with `cl100k_base`. Fixed windows follow token positions; section chunks follow Markdown headings; semantic chunks use adjacent sentence/unit embedding distances and a per-document 65th-percentile threshold. These values are implementation defaults rather than a demonstrated optimum. Overlap applies when a group exceeds the token bound, not between every natural section or semantic group. See [chunking comparison](chunking-comparison.md) for exact semantics.

Dense and BM25 retrieval apply the effective metadata scope. Hybrid ranking uses reciprocal rank fusion with constant 60. Optional cross-encoder scores have a different scale from vector/fusion scores; none is a calibrated confidence probability. Metadata filtering reduces the candidate scope and can also exclude relevant evidence when the user's constraints are wrong.

The active LangGraph performs retrieval, generation with claim validation or refusal, and finalization with timing. The generation prompt requests at most three source-worded claims with retrieved chunk citations; this is a model instruction, not an enforced claim-count limit. Exact text membership checks are deliberately conservative. They do not prove that a copied passage answers the question, that a source is factually correct, or that the answer covers all required facts. Missing evidence produces an explicit fallback. A generated answer can also fail because of a provider or model error; such failures must remain visible.

The current active evaluation sets contain 30 held-out question/unsupported cases and 25 development examples. Calibration cases and legacy report-only fixtures are excluded. The expansion includes ambiguous terminology questions, three questions requiring facts from distinct documents, and unsupported controls. Gold answers were authored against existing synthetic sources. Development examples were authored alongside their sources; these sets are useful comparisons within this library and are not independent external validation.

The paired comparison crosses three chunkers, dense/hybrid retrieval and reranking off/on: 12 configurations using the same selected cases and binding scopes. Retrieval metrics operate on deduplicated source document IDs. Empty gold sources have unavailable retrieval relevance metrics rather than automatic perfect scores. Generated-answer abstention can be measured on unsupported controls; retrieval-only runs do not establish answer quality. Failed configurations remain visible in coverage denominators. Faithfulness remains unavailable unless a separate judge actually measures it.

Run identities include source corpus, case-set hash, embedding identity, chunking configuration, retrieval settings and, for generated answers, generation provider/model. Historical rows with incompatible identities are rejected as current. See [evaluation results](evaluation-results.md) for actual completed runs, timing, errors and metric coverage; no technique is assumed to win in advance.

Campaign source data distinguishes observed attribution from causal lift. Direct mail uses 60 days from mail/drop and display uses 30 days from exposure; the source excludes conversions before the anchor or after its boundary. The library lacks randomized causal lift, financial return for ROI and exact-age outcome breakdowns. A RAG answer must preserve those limits instead of inferring unmeasured outcomes.

If a generated quote omits citations, the validator can attach a source ID only when the nonempty exact quote occurs in exactly one retrieved source. It rejects ambiguous matches and incorrect explicit IDs. Generated-score identity includes the prompt, response schema and grounding contract version to prevent stale measurements from appearing current.


For narrow single-campaign objective or activation/channel-count questions, the answer path can extract source-supported facts before calling the model. A complete objective section must already occur in the retrieved text and match its hashed parent source. Table answers require integral nonnegative actual counts, consistent campaign/period, unique field values and reconciliation of channel counts to the total. The complete query must match a narrow supported intent; extra requested facets or mismatched explicit campaign scope fall back to Ollama. Derived count claims carry raw table-row/header proofs and source IDs. These are deterministic source projections, not verbatim model claims or semantic entailment scores.
